# PWA deployment notes

Serve the web app and Fastify API on the same HTTPS origin whenever possible. Build production with `VITE_APP_MODE=api` and an empty `VITE_API_URL`; the web client then uses relative `/api` requests. Set `VITE_API_URL` only when the API is intentionally on another origin and configure CORS explicitly.

`bun run build:web` writes the client bundle (hashed assets, icons, fonts, `offline.html`, `manifest.webmanifest`, `sw.js`) to `apps/web/dist/client` and the SSR server bundle to `apps/web/dist/server`. Workbox reads `dist/client`, so the precache manifest covers the real shipped shell; check the build log for `precache N entries` before shipping. The shared Vite wrapper currently pins Nitro's Cloudflare module preset, so `dist/server/index.mjs` is a Worker entry rather than a Node server — a self-hosted Node runtime needs the preset overridden in the deployment checkout (`nitro: { preset: "node-server" }` applied outside the shared wrapper). Fastify remains on `3333`. The Nginx example's `map` belongs in the `http {}` block (Caddy needs no equivalent).

Publish the web output as a release, not by replacing a live directory. For example: build in a staging checkout, move the completed `dist` to `/srv/kotoba/releases/<build-id>/dist`, atomically switch `/srv/kotoba/current` to that release, then restart the server process from `/srv/kotoba/current/dist/server`. Keep the previous release until the new worker activates and health checks pass.

`deploy/Caddyfile` and `deploy/nginx.conf` include HTTPS, security headers, and the required cache policy. Stable filenames (`sw.js`, `manifest.webmanifest`, `offline.html`, favicons, touch icons, `/icons/*`, and `/fonts/*`) must revalidate because their content can change without their URL changing. Only Vite content-hashed files under `/assets/` receive a one-year `immutable` policy. Never proxy or cache any authenticated request, audio, recordings, feedback, diagnostics, provider, realtime, or mutation route in an edge cache. API responses default to `private, no-store`; only unauthenticated public prompts may be short-lived.

The service worker uses `injectManifest` and `registerType: prompt`. It precaches the hashed shell plus the offline page, icons, and local fonts. Navigation is NetworkFirst with `/offline.html` fallback; public `GET /api/prompts` has a short bounded cache. All other `/api` routes are NetworkOnly. Deploy the new build atomically, keep the previous build available until the new worker activates, and bump the cache names in `apps/web/src/sw.ts` when changing cache semantics.

Do not auto-reload while recording, saving a draft, reviewing an unsubmitted recording, uploading, or processing. The UI asks for update confirmation and disables confirmation while busy. A completed API-mode take is written to IndexedDB as `recorded-unsent` before the stop action completes; it is restored for playback after a reload and is never uploaded until the learner submits it. Recording again explicitly removes that draft. If an update is stuck, submit or discard the restored take, accept the prompt, and verify the new `sw.js` response is not served from a stale proxy cache.

The IndexedDB outbox is scoped by `learnerId` and uses a client-generated `clientAttemptId`; startup after learner bootstrap, restored visibility, network recovery, and manual retry perform foreground sync. Background Sync is not required. Lifecycle recovery is best-effort: an iOS force-kill or OS suspension can discard in-memory chunks even though visibility, pagehide, track, MediaRecorder, and AudioContext interruptions attempt to finalize a Blob.
